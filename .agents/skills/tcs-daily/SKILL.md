# TCS Daily

为有本科算法与复杂性基础、但不了解具体子方向的读者写论文解读。区分论文的主张、已核对的依据与自己的判断；不编造结果、背景或引用。

## 工作流：完成的检查直接复用

按当前任务进入相应阶段，不从头重跑。阶段提示给出日期、论文、输入输出路径；写作、评分和复核标准以本 skill 为准。

| 阶段 | 读取与产出 | 本阶段负责的检查 |
|---|---|---|
| 筛选 | 一次读取候选摘要与 `tags`，按需查记忆；写 selection JSON | 入选理由、话题覆盖、canonical tags；不下载 PDF，不给全文评分 |
| 单篇分析 | 一次读取预提取全文，复用提供的记忆；写带评分的论文块并记录论文记忆 | 主结果及关键论据核查、一次正文冷读、两项评分 |
| 总装 | 一次读取 selection 和各篇稿件；编写按语、组合论文块、更新 manifest | 跨篇术语、明显套话、结构与实际改动；继承单篇核查和评分 |
| 最终验证 | 主程序运行一次 `validate --selection ... --require-scores` | 报告、manifest、selection 一致，评分完整且合法；通过即结束 |

### 复用与补查

- 同一上下文已读过的 skill、范文、tags、全文或查询结果直接复用。长全文先保存到本地，再按定理编号、关键词或段落范围读取；不要反复打印整份 JSON。不同 agent 首次读取其必要输入是正常交接。
- 上一阶段提供的摘要与核查记录优先使用。知识库没有具体问题就不查，不必每次先跑 `stats`、遍历 `topics`，也不重复查询已给出的记忆。
- 筛选只用缓存摘要、tags 和记忆；单篇分析只用已提取全文、原文参考文献、记忆与本地往期日报；总装只用本地文件。这三个流水线阶段不再发起外部搜索或网络请求。
- 主结果核查、概念覆盖、可读性与评分合为单篇的一次复核。修正后只检查改动及受影响的结论，不重新逐项检查整篇；不要为了提高分数循环重写。
- 总装不重复单篇完整冷读或论文核查。出现具体矛盾、关键条件遗漏、来源版本变化或修改了技术论断时，才定向回看相关定理/引理，并更新受影响的评分及依据。纯排版调整不触发重新评分。
- 总装仅在有措辞问题需要参考时读范文；继承 selection 的 tags，仅在需要改 tag 且当前没有允许集合时调用 `tags`。最终合法性由 validator 检查。
- 旧稿缺评分时，先读取该论文已有核查记忆，再补看支撑置信度所需的原文局部；写作分基于最终正文。不能把“文件存在”当成“已核查”，也不为补两项分数重做所有稿件。
- 不同论文中的必要概念解释可以重复，每个可折叠论文块都必须独立可读。跨篇只消除无信息量的套话，不为了风格统一重写已经合格的正文。
- 使用 `run_codex.py` 时，总装 agent 更新 manifest 后结束，最终验证交给主程序。独立手工生成日报时，由当前 agent 运行一次验证。失败只修返回的问题及受影响部分；内容改变后再验证，输入未变且已通过则不重复跑。

## 按需加载与 token 预算

- **筛选**只读本页和候选摘要，不加载写作细则、范文或 PDF。
- **单篇分析**读取一次 [写作与评分](references/writing.md)，复用已有核查证据完成两项评分；无需额外发起独立审稿。范文仅在需要风格参照时读少量相关段落。
- **总装**按本页组合稿件并保留评分；只有补写或重新评分时才读 [写作与评分](references/writing.md) 的对应部分。
- 全文 JSON 只在本地保存，按 section/关键词输出需要的内容；`full_text` 和分节有重叠，不把同一内容读两遍。先读定义、主定理和关键证明链，外围证明或附录仅在影响理解、判断或评分时补读。
- 合格的草稿通过文件拼接保留，仅对问题段落打补丁；不要让模型逐字重新输出全部已有稿件。最终回复只报产物、验证结果和实质问题，不重贴日报。
- 缩减的是重复输入、工具输出和无依据的返工；不牺牲主结果核查、核心背景与解释，不以摘要代替论文证据。

每篇末尾必须有 **结果置信度** 和 **写作质量** 两项评分，各为 0–10 分（可有小数，越高越好）并附一句具体依据。后一项评价最终日报解读的清晰自然程度和 AI 腔，不能当作真实 AI 生成概率。具体尺度在写作参考中；尤其检查“语言流畅却无法复述关键操作”“用专业措辞和结论式过渡掩盖推理缺口”的假解释，不凭术语、公式和例子的存在给高分。

## Markdown 与输出

最终日报写入 `posts/YYYY-MM-DD.md`。开头是 YAML frontmatter；编辑按语在论文块外，未入选但值得关注的内容放在全部论文块之后。每篇块内标题用 `##`（折叠标题由前端提取），若确需内部小节用 `###`，不使用 `#`。

````markdown
---
date: 2026-03-04
---

## 编辑按语
不超过 300 字，概述入选方向，有真实联系才谈共同主题。

::::issue[exact-algorithms]
## 论文标题 [arXiv:2603.03219](https://arxiv.org/abs/2603.03219)

完整、自包含的解读正文。

**结果置信度：8.0/10** — 本篇已核查的具体依据及主要保留。

**写作质量：5.0/10** — 本篇影响理解的具体障碍及其后果；数字仅为格式示例。
::::

## 未入选但值得关注
按 selection 的 skipped_notable，每篇 1-2 句话；无内容可省略。
````

- `::::issue[tags]` 与关闭 `::::` 均独占一行。tags 只能来自 `tcs-daily tags`，每篇默认 1 个，两个独立主要贡献才用 2 个；按主定理的研究问题选最具体标签，不按标题热词/应用/工具选，不新建标签。静态标签表不另维护，以命令返回为准。
- 数学只用 `$...$` 和 `$$...$$`，不使用反引号、`\(...\)`、`\[...\]` 或代码块包裹数学。算子名用 `\mathrm{}`，多行公式用 `aligned`。总装保留公式内容。
- 引用用 `作者 (年份)` / `作者 et al. (年份)`；arXiv 用 `[arXiv:ID](https://arxiv.org/abs/ID)`，只去掉末尾版本号也可，不猜编号。往期链接用 `[YYYY-MM-DD 日报](#YYYY-MM-DD)`。脚注可补充说明，不用作参考文献列表。
- 旁注只补充正文已解释过的严格定义、历史或技术细节，按需 1-3 个，不必凑数。读者不展开旁注也应读懂全文。语法如下，可嵌套于 issue 内：

```markdown
:::aside[补充定义]
正文已解释直觉，这里补形式化定义或延伸细节。
:::
```

标准 Markdown 加粗、斜体、表格、引用和分隔线可用，不使用 HTML 标签。

## 工具与记忆

通过 PATH 中的 `bin/tcs-daily` 调用，输出 JSON。日期和 arXiv ID 以下仅作示例；按当前任务替换。

```bash
# 数据获取；流水线由主程序预备，agent 按阶段读取缓存
tcs-daily fetch 2026-03-04
tcs-daily metadata 2603.03219v1
tcs-daily download 2603.03219v1
tcs-daily extract 2603.03219v1

# 定向查记忆/往期，已提供上下文时不重复查
tcs-daily memory search "lattice problems"
tcs-daily memory topics "complexity"       # 无参数可列所有主题
tcs-daily memory entries "covering radius"
tcs-daily memory paper 2603.03219v1
tcs-daily memory date 2026-03-03
tcs-daily memory stats
tcs-daily history "steiner tree"

# 每篇完成时一次记录；summary 包含结论、核查位置、疑点和评分依据
tcs-daily memory record-paper '{"arxiv_id":"...","title":"...","tags":["..."],"summary":"...","included":true,"report_date":"..."}'
tcs-daily memory link-topic 2603.03219v1 "lattice problems"
tcs-daily memory record-entry <key> <value> <category>
# category: result | technique | concept | open_problem | definition

# 结构与发布文件
tcs-daily tags
tcs-daily manifest 2026-03-04 posts/2026-03-04.md 5
tcs-daily validate 2026-03-04 --selection data/cache/selection/2026-03-04.json --require-scores
```

`extract` 返回 `abstract`, `introduction`, `main_results`, `techniques`, `conclusion`, `full_text`；section 为空就在 `full_text` 中定位。严禁自己写 PDF 解析代码、安装额外 PDF 工具或绕过 CLI 写抓取逻辑。提取不足在具体受影响处说明，并反映到结果置信度中。

`memory.db` 跨天持久化。记录有复用价值的定理/界、方法、概念、开放问题与研究趋势；论文记忆让后续阶段和日期沿用已做的核查。更新条目只在结论或核查依据变化时进行。

默认 `validate` 保持兼容旧日报；`--require-scores` 额外检查每个论文块末尾的两项分数、范围与非空依据，不能判断评分是否学术合理。新日报流程始终带该选项。

## 工具维护边界

生成日报时若发现 CLI 缺少必要功能，可在 `tcs_daily/` 追加兼容功能，并在此记录；不要自行改动已有接口行为、`run_codex.py` 或前端。用户明确要求维护 skill/工作流时，可同步更新对应阶段提示与调度，保留无关运行配置。
