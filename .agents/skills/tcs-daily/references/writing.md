# 单篇写作与评分

单篇分析时读取；总装仅在需要补写正文或补评、重评分时参考。不要在筛选阶段加载。

## 无背景读者协议

写作前在心里按依赖顺序整理理解主结果所需的 3-6 个前置概念，不把清单原样写进正文。

- 开头 1-2 段讲清研究问题、输入对象/模型和主结果，先给事实再给评价。
- 铺好背景：研究动机、核心对象的直觉、可比较的 prior work 时间线（适用范围、定量界、作者年份）、留下的缺口和本文推进之处。已确认的关键结果附原文链接，引用往期用 `[之前的日报](#YYYY-MM-DD)`。
- 至少一个最小 running example 贯穿问题定义、主结果和技术思路。
- 非本科水平概念首次出现时，在正文解释它解决什么困难、直觉或例子、必要定义及本文中的作用。符号先交代对象类型和量化范围；缩写首次展开。旁注不能代替必要的解释。
- 主定理用 LaTeX 精确陈述，保留假设、量词、参数范围、概率/计算模型和复杂度依赖；与 prior best 在相同条件下比较。讲清关键技术为什么能奏效，而非罗列术语。
- 完稿时合并冷读与事实核查：不展开旁注，读者应能复述输入、目标、主结果、相对已有工作的改进和技术思路。只修实际缺项。

## 写作规范

正文是连贯的研究分析，通常每篇 3000-6000 字；技术确实简单可约 1500 字，不为压缩篇幅删掉解释。保留专业英文术语，中文叙述；技术步骤可以列举，全文不要变成 bullet 摘要。

个人判断要具体，融入技术分析。例如解释某个转化为什么绕过了原方法的瓶颈。不要伪装人类身份、阅读经历或情绪来制造“个人声音”。拿不准的地方，在受影响的具体论断旁说明；不要每篇附统一的 PDF 质量声明。

避免空洞赞叹、裸用术语、悬浮评论腔和重复转折。开头不要用“真正钉住的不是……而是……”或带引号的标签词代替对象与结果。不要用 emoji、收束套话，或强套“背景→贡献→技术→展望”的编号结构。不要单列“评价与展望”“讨论”“总结”，也不要每篇重复“价值→局限→follow-up”结尾；按内容自然停住即可，无需强求每篇结尾互不相同。固定评分行是元信息，不要求改换句式。

风格标杆为 `posts/2026-03-05.md`（相对仓库根目录）。本页规范已足够时无需另读；需要参照具体写法时，只读相关段落或一个论文块，不加载整期。新评分格式以本页为准，范文没有评分不代表可以省略。

## 两项评分

每篇入选论文的解读都必须在**正文末尾、该 `::::issue` 的关闭标记之前**给出以下两项分数与各一句具体依据。不放在旁注、编辑按语或整个日报末尾的统一总评中，不对未阅读全文的候选硬打分。

两项均为 **0–10 分（含端点）**，可有小数，通常保留一位；分数越高越好。分别打分，不合成总分，不机械给所有论文同分。使用本次阅读与合并复核已有的证据，不为打分额外启动一轮全面审稿。

### 结果置信度

衡量对所解读主结果的可信把握：精确定理是否与原文一致、关键假设与适用范围是否明确、核心证明步骤核对到何处、是否存在漏洞或提取歧义。它不是论文重要性、新颖性、作者声望或“定理为真的概率”。不能因行文流畅或作者知名而给高分。

| 分数区间 | 参考尺度 |
|---|---|
| 0 ≤ 分数 < 3 | 主结果无法确认，或发现尚未解决的严重矛盾/证明缺口 |
| 3 ≤ 分数 < 5 | 主要依赖摘要、引言或作者转述，关键条件/证明证据不足 |
| 5 ≤ 分数 < 7 | 已核对定理和主要假设，证明只读到概述或仍有实质疑点 |
| 7 ≤ 分数 < 9 | 已核对主定理及关键证明链，所查部分自洽；说明未独立检查的环节 |
| 9 ≤ 分数 ≤ 10 | 关键推导已实质检查、假设与引用依赖清楚，未发现显著疑点；高分必须有相应依据 |

依据点名原文定理/引理或具体检查范围，并指出影响把握的主要保留。阅读覆盖有限就如实降分，不冒充完成了独立证明或形式验证；高分也不表示绝对正确。conditional result 的清楚声明本身不应被当成证明缺陷。

### 写作质量

评价 **agent 写出的最终日报解读**，不评价原论文作者的文风。看本科 CS 读者能否跟上、术语与符号是否解释到位、例子是否有效、语言是否直接自然，以及套话/重复/刻意修辞的多少。

**以读者实际能否理解为准，不按写作要素是否齐全打勾。** 有术语译名、有定义、有例子、没有套话，都不足以证明文章易懂。评分时暂时放下自己从原论文读到的知识，只使用日报正文已经交代的信息；不能在脑中替作者补齐中间步骤。流畅、严谨、信息密度高与说人话是不同的优点。

在已有的一次冷读中，重点看最难且支撑主贡献的 1-2 个段落，尝试仅凭正文回答：这一段要解决什么困难？对什么对象做了什么操作？为什么这一步有用？例子能否具体展示这一步的输入、变化和结果？答不上来就定位缺失的解释，不因前半篇背景好而忽略技术核心。无需新增一轮审稿或输出检查清单。

#### 识别“像没理解就生成出来”的文字

判断的是正文是否传达了理解，不据文风断言生成来源或作者心理。重点识别以下可定位的问题，而不是查某几个禁词：

- **宣布解释完成，却没有解释**：“这解释了为什么”“关键在于”“恰好对应”之后，是否真给出了中间关系？删去这句评论后若只剩两个不相连的结论，就是用语气代替推理。
- **用专业措辞掩盖空缺**：“概率支付权重”“结构实现了抵消”等话，能否改写为明确的对象、操作和后果？写不出具体含义就不算解释；贴上英文名或公式也不能补救。
- **例子与证明脱节**：例子是否真正演示了困难步骤，还是只在开头定义模型、结尾再次点名？不得用“贯穿全文”奖励装饰性例子。
- **个人判断可以任意替换**：“最让我意外”“最巧的一步”是否指出了原先的困难、看似可行却失败的办法，以及本文为何有效？只有赞叹和第一人称，不构成理解证据。
- **局部顺滑、整体无法复述**：段段都有过渡与收束，读完却说不出算法如何运作、论证如何推进；大量新名词和恒等式只靠“因此”串起来，是实质的写作缺陷。

这些信号要结合上下文：一个专业词或转折句本身不扣分，技术难、公式多也不自动低分；必须指出它在本篇遮住了哪一步。若核心部分同时存在连续推理缺口和这种空泛解释感，通常落在 **3–4 分**，不能因为语法顺畅而给到 5 分以上。把准确写明“这里引用一个已知引理，作用是……”与假装已经讲清证明区分开。

用户所说的“AI 生成率”在这里作为 **AI 腔与模板感** 的编辑观察：高分表示更清楚、更自然、模板感更少。它不是 AI 检测器结果、真实生成比例或作者身份判定；不另报虚构的百分比，也不把公式多、术语英文或技术困难本身当成扣分项。

| 分数区间 | 参考尺度 |
|---|---|
| 0 ≤ 分数 < 3 | 核心对象讲不清，术语与空话堆积，读者很难跟随 |
| 3 ≤ 分数 < 5 | 能辨认问题和结果，但关键思路依赖读者补充专业知识，大片技术段落无法跟随 |
| 5 ≤ 分数 < 7 | 问题和背景可读，部分技术也能理解，但主贡献的解释存在明显断点；5 分表示只读懂了半篇，不是基本合格的高分 |
| 7 ≤ 分数 < 9 | 读者能复述主方法为何奏效，关键步骤有实质解释；仅局部细节费力，8 分以上要求技术核心也可跟随 |
| 9 ≤ 分数 ≤ 10 | 不借助原论文或子领域训练也能跟随完整主线；难点被具体拆解，不需要读者自行搭桥，少用此档 |

先按上表定位，再应用以下上限；不通过平均前后段的优点掩盖核心障碍：

- 主贡献的技术解释连续多段只给定义、恒等式或结论，缺少操作与因果连接：**最高 5.0 分**。即使背景清楚、数学准确，也不能称为“局部较密集”。
- 主线某个必要步骤只能靠未解释的专业知识跨过去：**最高 6.0 分**。正文若明确只省略不影响主线的证明细节，不适用此上限。
- 例子只解释了问题设定，却没有帮助理解后续困难步骤，不得把“例子贯穿全文”作为加分依据；比喻没有对应到具体对象与操作，同样不算解释。

依据优先指出决定分数的具体障碍及其后果，再简述优点；不把核心断裂淡化成“参数稍密”“仍需集中阅读”。分数可以高，但必须能说明最难的主线段落为什么也可读，不以 8 分为默认起点。总装改动解释或语言质量时更新此分；纯粹搬运正文保留原评分。

校准例：`posts/2026-09-22.md` 的 **A general counting and sampling Lovász local lemma**（arXiv:2609.23671）应约 **4.0/10**，原先的 8.5 分偏高。找解/计数/采样的背景清楚，但从分布差恒等式到 corridor、条件候选列表与 signed-flow 能量，读者无法仅凭正文还原关键操作及其联系。三子句例子解释了依赖关系和局部抵消，没有展示采样器如何改变分布，不能据此声称最难部分也讲清楚了。“概率支付权重”“这一配对保证可逆性”等句子还营造了已经解释清楚的语气，却没有交代相应操作或理由。这个案例用于校准尺度，不要求每次再打开全文。

固定输出格式（下面数字仅示范，不能照抄评分）：

```markdown
**结果置信度：8.0/10** — 已核对 Theorem 1 的假设及 Lemma 3 的归约，附录的常数估计未逐步复算。

**写作质量：5.0/10** — 背景清楚，但辅助链与条件候选列表缺少具体操作解释，三子句例子未说明采样分布如何改变。
```
